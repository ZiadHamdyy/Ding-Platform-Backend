# Deploying Ding Platform Backend to Render

This guide will walk you through deploying the Ding Platform Backend to Render, a cloud platform that provides managed PostgreSQL and Redis.

## 📋 Prerequisites

Before deploying to Render, you need:

1. **Render Account**: Sign up at [render.com](https://render.com)
2. **Neo4j Database**: Since Render doesn't provide Neo4j, you'll need:
   - **Neo4j Aura** (recommended): Free tier available at [neo4j.com/cloud/aura](https://neo4j.com/cloud/aura)
   - Or self-host Neo4j on another platform
3. **Cloudinary Account**: For media uploads (free tier available)
4. **SMTP Service**: For email functionality (Gmail, SendGrid, etc.)
5. **Google OAuth Credentials** (optional): For Google authentication

## 🚀 Deployment Methods

### Method 1: Using render.yaml (Recommended - Infrastructure as Code)

This method uses the `render.yaml` file to automatically provision all services.

#### Steps:

1. **Push your code to GitHub**
   ```bash
   git add .
   git commit -m "Prepare for Render deployment"
   git push origin main
   ```

2. **Create New Blueprint Instance**
   - Go to [Render Dashboard](https://dashboard.render.com)
   - Click "New +" → "Blueprint"
   - Connect your GitHub repository
   - Select your repository and branch
   - Render will detect `render.yaml` and show all services

3. **Review Services**
   
   The blueprint will create:
   - **Web Service**: `ding-backend` (Node.js backend)
   - **PostgreSQL Database**: `ding-postgres`
   - **Redis Instance**: `ding-redis`

4. **Configure Environment Variables**
   
   Before deploying, set these environment variables manually in the Render dashboard:

   **Required:**
   - `NEO4J_URI`: Your Neo4j connection URI (e.g., `neo4j+s://xxxxx.databases.neo4j.io`)
   - `NEO4J_AUTH`: Neo4j credentials (format: `neo4j/your-password`)
   - `CLOUDINARY_CLOUD_NAME`: Your Cloudinary cloud name
   - `CLOUDINARY_API_KEY`: Your Cloudinary API key
   - `CLOUDINARY_API_SECRET`: Your Cloudinary API secret
   - `SMTP_HOST`: Your SMTP server (e.g., `smtp.gmail.com`)
   - `SMTP_USER`: Your SMTP username/email
   - `SMTP_PASS`: Your SMTP password
   - `SMTP_FROM_EMAIL`: Sender email address
   - `GOOGLE_CLIENT_ID`: Google OAuth client ID
   - `GOOGLE_CLIENT_SECRET`: Google OAuth client secret
   - `GOOGLE_CALLBACK_URL`: Your callback URL (e.g., `https://your-app.onrender.com/api/v1/auth/google/callback`)

   **Auto-generated:**
   - `JWT_SECRET`: Auto-generated by Render
   - `SESSION_SECRET`: Auto-generated by Render
   - `DATABASE_URL`: Auto-connected from PostgreSQL
   - `REDIS_URL`: Auto-connected from Redis

5. **Update Frontend URLs**
   
   In the Render dashboard, update these variables:
   - `FRONTEND_URL`: Your frontend deployment URL
   - `FRONTEND_URLS`: Comma-separated list of allowed origins

6. **Deploy**
   - Click "Apply" to create all services
   - Render will build and deploy your application
   - Monitor the deployment logs

### Method 2: Manual Service Creation

If you prefer manual setup or want more control:

#### 1. Create PostgreSQL Database

- Go to Render Dashboard → "New +" → "PostgreSQL"
- **Name**: `ding-postgres`
- **Database**: `ding_db`
- **User**: `ding_user`
- **Region**: Choose closest to your users
- **Plan**: Free or Starter
- Click "Create Database"
- **Save the connection details** for later

#### 2. Create Redis Instance

- Go to Render Dashboard → "New +" → "Redis"
- **Name**: `ding-redis`
- **Region**: Same as PostgreSQL
- **Plan**: Free or Starter
- **Maxmemory Policy**: `allkeys-lru`
- Click "Create Redis"
- **Save the connection URL**

#### 3. Create Web Service

- Go to Render Dashboard → "New +" → "Web Service"
- Connect your GitHub repository
- **Configuration**:
  - **Name**: `ding-backend`
  - **Region**: Same as databases
  - **Branch**: `main` (or your default branch)
  - **Root Directory**: Leave empty
  - **Runtime**: `Node`
  - **Build Command**: `pnpm install && pnpm prisma generate && pnpm run build`
  - **Start Command**: `sh scripts/render-start.sh`
  - **Plan**: Free or Starter

#### 4. Configure Environment Variables

In the web service settings, add all environment variables (see list above).

For database connections:
- `DATABASE_URL`: Copy from PostgreSQL service "Internal Database URL"
- `REDIS_URL`: Copy from Redis service "Internal Redis URL"

#### 5. Deploy

- Click "Create Web Service"
- Render will build and deploy your application

## 🗄️ Setting Up Neo4j Aura

Since Render doesn't provide Neo4j, use Neo4j Aura:

1. **Create Free Instance**
   - Go to [console.neo4j.io](https://console.neo4j.io)
   - Click "New Instance"
   - Select "AuraDB Free"
   - Choose a region close to your Render services
   - **Save the credentials** shown after creation

2. **Get Connection URI**
   - Format: `neo4j+s://xxxxx.databases.neo4j.io`
   - Copy this URI

3. **Configure in Render**
   - Set `NEO4J_URI=neo4j+s://xxxxx.databases.neo4j.io`
   - Set `NEO4J_AUTH=neo4j/your-password`

4. **Configure Network Access** (if needed)
   - Neo4j Aura Free allows all IPs by default
   - For paid plans, whitelist Render's IPs

## 🔧 Post-Deployment Configuration

### 1. Run Database Migrations

Migrations run automatically on startup via `render-start.sh`. To run manually:

```bash
# In Render Shell (Dashboard → Service → Shell)
pnpm prisma migrate deploy
```

### 2. Seed Database (Optional)

```bash
# In Render Shell
pnpm run prisma:seed
```

### 3. Verify Health

Visit: `https://your-app.onrender.com/health`

Expected response:
```json
{
  "status": "ok",
  "timestamp": "2025-12-01T14:22:41.000Z",
  "uptime": 123.45,
  "environment": "production"
}
```

### 4. Check API Documentation

Visit: `https://your-app.onrender.com/api/docs`

### 5. Update Frontend

Update your frontend to point to the new backend URL:
```env
VITE_API_URL=https://your-app.onrender.com
```

## 🔒 Security Best Practices

### 1. Environment Variables

- ✅ Use Render's environment variables (encrypted at rest)
- ❌ Never commit secrets to git
- ✅ Rotate secrets regularly

### 2. Database Security

- ✅ Use internal database URLs (not external)
- ✅ Enable SSL connections
- ✅ Regular backups (automatic on paid plans)

### 3. CORS Configuration

Update allowed origins in environment:
```env
FRONTEND_URLS=https://yourdomain.com,https://www.yourdomain.com
```

### 4. Rate Limiting

Already configured in the application (100 requests/minute).
Adjust in environment variables if needed:
```env
RATE_LIMIT_WINDOW_MS=60000
RATE_LIMIT_MAX_REQUESTS=100
```

## 🐛 Troubleshooting

### Service Won't Start

1. **Check Build Logs**
   - Dashboard → Service → Events → Build logs
   - Look for errors during `pnpm install` or `pnpm build`

2. **Verify Environment Variables**
   - Dashboard → Service → Environment
   - Ensure all required variables are set

3. **Check Database Connections**
   ```bash
   # In Render Shell
   echo $DATABASE_URL
   echo $REDIS_URL
   echo $NEO4J_URI
   ```

### Database Migration Issues

```bash
# Reset migrations (⚠️ This will delete data)
pnpm prisma migrate reset --skip-seed

# Or run specific migration
pnpm prisma migrate deploy
```

### Neo4j Connection Problems

1. **Verify credentials**:
   - Check `NEO4J_AUTH` format: `neo4j/password`
   - Ensure URI uses `neo4j+s://` for SSL

2. **Test connection**:
   ```bash
   # In Render Shell
   curl -u neo4j:password https://your-instance.databases.neo4j.io:7687
   ```

### High Memory Usage

- Reduce Neo4j connection pool size
- Optimize database queries
- Upgrade to higher tier
